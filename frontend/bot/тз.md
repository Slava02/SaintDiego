# Разработка Telegram-бота для записи бездомных людей в центры социальной поддержки

Данный документ содержит детальное проектирование Telegram-бота для волонтеров благотворительной организации. Система позволит оптимизировать процесс записи бездомных людей в центры социальной поддержки. 
Ключевые особенности: регистрация волонтеров, поиск посетителей, запись на услуги с учетом различных ограничений, просмотр истории и управление записями. 
Интерфейс ориентирован на интуитивную понятность и простоту использования, учитывая различные сценарии взаимодействия.


### Регистрация и авторизация волонтера

1. **Начало работы**
   - Пользователь запускает бота командой /start
   - Проверка наличия пользователя в базе данных
   - Если пользователь не зарегистрирован → переход к регистрации
   - Если пользователь зарегистрирован → проверка членства в необходимых чатах

2. **Процесс регистрации**
   - Запрос ФИО (текстовое сообщение)
   - Запрос даты рождения
   - Проверка членства в необходимых чатах
   - Если проверка успешна → переход к главному меню
   - Если не состоит в чатах → отправка ссылок и инструкций

   API: 
   POST /volunteers - создание нового волнтера
   GET /volunteers/{tg_id} - получение волонетра по id в телеграм 

### Главное меню и поиск посетителей

3. **Главное меню**
   - Кнопка "Записать существующего посетителя"
   - Кнопка "Записать нового посетителя"
   - Кнопка "Мой профиль"

   
4. **Поиск посетителя**
   - Запрос на ввод ФИО посетителя
   - Использование inline режима для поиска с выводом похожих результатов
   - Если посетитель найден → отображение профиля
   - Если посетитель не найден → предложение зарегистрировать нового

   API:
   GET /clients Получение списка живых клиентов

   Клиенты хранятся в памяти и один раз в день обновляется список по cron job

### Работа с профилем посетителя

5. **Отображение профиля посетителя**
   - Основная информация о посетителе (ФИО, ID, Фото)
   - История последних 5 записей
   - Предстоящие записи
   - Список доступных услуг с пагинацией, должен отображаться в удобном виде. В услугу входит: название, место, время

   API:
   GET /clients/{id} Получение клиента по идентификатору
   GET /clients/{id}/services Список доступных клиенту услуг
   GET /clients/{id}/events?prev=x  Список записей клиента


6. **Запись нового посетителя**
   - Запрос имени и фамилии
   - Отображение ближайших доступных дат для анкетирования
   - Выбор даты и времени
   - Подтверждение записи
   - Сообщение об успешной записи

    API:
   GET: /events/services/{id}
   PUT: /events/{id}/participants

7. **Запись существующего посетителя**
   - Отображение доступных услуг с учетом ограничений
   - Выбор услуги
   - Выбор даты из календаря
   - Выбор времени
   - Подтверждение записи
   - Сообщение об успешной записи

     API:
   GET: /events/services/{id}
   PUT: /events/{id}/participants
   
8. **Особые случаи**
   - Для заблокированных посетителей:
     * Отображение информации о блокировке и причина
     * Доступна только запись на консультацию
   - Для посетителей, отсутствовавших более года:
     * Информационное сообщение о длительном отсутствии
     * Доступна только запись на повторное собеседование


## Компоненты для реализации Telegram-бота

### Технологический стек

Телеграм бот будет использовать готовый бек-енд, и является только интрефейсом для взаимодействия с пользователем.

- **Язык программирования**: Python как оптимальный вариант для разработки Telegram-ботов благодаря богатым библиотекам
- **Фреймворк**: aiogram 3.x (асинхронная библиотека, обеспечивает высокую производительность и удобный API)
- **Модуль** aiogram-dialog для создания интерактивных меню
- **fuzzysearch** для реализации нечетого поиска по ФИО


### Элементы пользовательского интерфейса

1. **Клавиатуры**
   - **ReplyKeyboardMarkup**: для главного меню и часто используемых команд
   - **InlineKeyboardMarkup**: для интерактивных действий (выбор услуг, дат, подтверждение)
   - **Календарный компонент**: специальный inline-компонент для выбора даты
   - **Пагинация**: для просмотра списков с большим количеством записей

2. **Поисковый функционал**
   - **InlineQuery**: для реализации поиска посетителей
   - **Разделение результатов**: отображение не более 5-7 результатов на одном экране
   - **Fuzzy-поиск**: алгоритм нечёткого поиска для нахождения похожих имён

3. **Обработка сообщений**
   - Фильтры сообщений для определения контекста взаимодействия
   - Конечные автоматы (FSM) для управления диалогом
   - Валидация ввода для предотвращения ошибок
