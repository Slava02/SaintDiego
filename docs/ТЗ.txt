Техническое задание

Система предназначена для оптимизации процесса оказания социальной помощи и управления потоком посетителей благотворительной организации.

Сервис Администратора
Функциональные требования

1. Управление временными слотами (вкладка "Расписание")

1.1. Просмотр временных слотов
- Разделение на вкладки:
 - "Активные" - текущие и будущие временные слоты
 - "Архивные" - прошедшие временные слоты
 - Отображение в формате таблицы со столбцами: название, тип, место, участники (макс. кол-во), статус и кнопка действия
API: GET /timeslots

1.2. Создание временного слота
- Доступ через:
 - Кнопку "Создать временной слот" в шапке
- Обязательные поля:
 - Название события
 - Дата и время
 - Тип (разовое/повторяющееся)
 - Место проведения. Место проведения можно выбрать из имеющихся или добавить новое, оно состоит из названия и адреса. Текщие места проведения должна быть возможность менять.
 - Максимальное количество участников. На разные услуги, которые доступны в таймслоте могут записываться одни и те же люди. Данные параметр отвечает за то, чтобы суммарное количество уникальных людей, записанных на услуги по данному таймслоту, не превышало максимально допустимое количество.
- Возможность добавления новых мест при создании 
- Для повторяющихся временных слотов:
 - Частота (ежедневно/еженедельно/ежемесячно/ежегодно)
 - Окончание (бессрочно/количество повторений/дата)
- Настройка услуг:
 - Кнопка для добавления услуги с выбором из предустановленных типов услуг
 - Указание времени проведения
 - Установка вместимости
 - Настройка окна бронирования. Данный параметр отвечает  максимально удаленное время через которое можно записаться на услуу. Например: если сегодня 01.03, а окно бронирования услуги 14 дней - то максимально я могу записаться на 14.03. Услуги после 14.03 не отображаются на текущий день. 
 - Кнопка для редактирования услуги
 - Кнопка для удаления услуги 
API: POST /timeslots

1.3. Фильтрация и поиск
- Поисковая строка для фильтрации по:
 - Названию временного слота
 - Месту проведения
- Расширенные фильтры:
 - Диапазон дат (с календарем)
 - Тип события (все/разовые/повторяющиеся)
- Возможность сброса всех фильтров
API: GET /timeslots

1.4. Управление временными слотами
- Действия для активных событий:
 - Редактирование
 - Архивация
 - Удаление
- Действия для архивных временных слотов:
 - Активация (с выбором новой даты для разовых временных слотов)
 - Удаление
- Подтверждение для критических операций:
 - Удаление временного слота
 - Архивация временного слота с участниками
API: 
- GET /timeSlots/{id}
- PUT /timeSlots/{id}
- DLETE /timeSlots/{id}
- PUT /timeSlots/{id}/activate
- PUT /timeSlots/{id}/archive

1.5. Автоматизация
- Сохранение состояния фильтров при переключении вкладок
- Адаптивное отображение для разных устройств


2. Управление мероприятиями (Вкладка "Мероприятия")

2.1. Просмотр мероприятий
- Разделение на "Предстоящие" и "Прошедшие" мероприятия
- Отображение в виде списка с колонками:
 - Название мероприятия
 - Дата и время
 - Место
 - Количество участников (текущее/максимальное)
 - Действия: редактирование самого мероприятия и редактирования участников мероприятия)

2.2. Фильтрация мероприятий
- По типу услуги
- По месту проведения
- По участнику

2.3. Редактирование мероприятия
- Возможность изменить только:
 - Время проведения
 - Вместимость (с проверкой: новая вместимость ≥ текущего числа участников)


2.4. Удаление мероприятия
- Подтверждение действия через диалоговое окно
- Дополнительное подтвеждение при наличии зарегистрированных участников


2.5. Редактирование участников мероприятия

2.5.1. Просмотр участников
- Отображение в виде таблицы с колонками:
 - ФИО
 - Статус (Присутствовал/Не пришел)
 - Имя, Фамилия, логин в телеграмм записавшего волнтера (если записал администратор - то просто указание admin)
- Отображение общего количества участников и максимальной вместимости


2.5.2. Добавление участника
- Поиск по ФИО, ID или телефону с автодополнением
- Проверка на:
 - Превышение вместимости мероприятия
 - Повторную регистрацию одного участника
- FAB-кнопка с иконкой "+" в правом нижнем углу

2.5.3. Управление статусами
- Групповое изменение статуса через чекбоксы
- Доступные статусы:
 - Присутствовал (зеленый)
 - Не пришел (красный)


3. Управление посещениями (вкладка "Настройки посещения")

3.1 Настройка услуг и правил посещения

3.1.1 Настройка предлагаемых услуг и ограничений по ним
- Список доступных услуг отображается таблицей (название услуги, ограничение в днях/неделях/месяцах, кнопка редактирования и удаления)
- Чтобы добавить новую услугу, нужно выбрат услугу из выпадающего списка и задать настройки посещения:
  - Как часто можно пользоваться услугой (в днях/неделях/месяцах)
- При нажатии на кнопк редактирования - открывается окно редактирования ограничения, в котором можно поменять минимальное количество дней, которое должно пройти между получением нескольких услуг такого типа
API:
- GET /services
- POST /services TODO
- GET /servies/{id}
- PUT /servies/{id} - Добавление или изменение настроек для услуги

3.2 Настройка отображения услуг

3.2.1 Блокировка пользователей
- Поиск пользователя по ФИО или id
- Блокировка пользователя с указанием причины
- Список заблокированных пользователей со следующими колонками: ФИО, дата блокировки, причина, кнопка разблокировать


Основные сценарии использования (юзкейсы)

1. Управление Таймслотами
Актор: Администратор
Цель: Создание и редактирование таймслота
Шаги:

2. Выбрать существующий таймслот или нажать на кнопку "создать тайм-слот"
3. Внести необходимые параметры таймслота, если нет нужного места создать его или отредактировать существующее. Добавить услуги и настроить нужные параметры для них.
4. Нажать на кнопку сохранить

2. Активация таймслотов
Актор: Администратор
Цель: Создание и редактирование таймслота
Шаги:
1. Перейти в раздел "Расписание"
2. Перейти в подраздел "архивные"
3. Выбрать таймслот и нажать на кнопку "активировать"
4. Для таймслотов с типом single (не повторяющиеся) - нужно указать дату


3. Управление мероприятиями
Актор: Администратор
Цель: Управление текущими мероприятиями и участниками
Шаги:
1. Перейти в раздел "Мероприятия"
2. Выбрать вкладку:
  - "Предстоящие мероприятия"
  - "Прошедшие мероприятия"
  - "Экспорт данных"
3. Просмотреть список мероприятий с информацией:
  - Название мероприятия
  - Дата и время проведения

Шаги:

2. Просмотреть текущий список (пример):
  - ID 3 Виктор Толстихин Записал: Петя Петров @tg_login (присутствовал)
  - ID 2 Анна Петрова Записал: Петя Петров @tg_login  (не явилась)
  - ID 1 Сергей Иванов Записал: Петя Петров @tg_login  (присутствовал)
3. Добавить нового участника через FAB-кнопку:
  - Поиск по ФИО/ID
  - Проверка на превышение вместимости
  - Подтверждение добавления


5. Редактирование мероприятия
Актор: Администратор
Цель: Изменение параметров существующего мероприятия
Шаги:
1. Выбрать мероприятие из списка
2. Отредактировать доступные параметры:
  - Время проведения
  - Вместимость (с проверкой на текущее количество участников)
3. Сохранить изменения или отменить

Цель: Отметка присутствия/отсутствия участников
Шаги:

2. Выбрать участников через чекбоксы
3. Изменить статус на:
  - "Присутствовал"
  - "Не пришел"

Цель: Отметка присутствия/отсутствия участников

2. Перейти во вкладку экспорта данных

5. Сохранить
6. Посмотреть список услуг и ограничений в таблице

Сервис записи
Функциональные требования для системы записи посетителей

1. Аутентификация и регистрация волонтера
- Регистрация волнтера с указанием: ФИО, даты рождения, аватарки
- Проверка на наличие волонтера в нужных чатах, если есть - то ему доступен весь функционал для записи

2. Запись посетителей на события
Это основной функционал. Волонтер записывает посетителей на услуги (события). Для этого - он должен найти посетителя по ФИО или ID и записаться его на доступные для посетителя услуги.

2.1 Ораничения на запись
2.1.1
Для некоторых групп посетителей доступны только определенные услуги:
- Для новых пользователей, которых нет в базе - доступно только услуга анкетирования. Для этого - нужно ввести имя и фамилию клиента и записать на ближайшее доступное анкетирование.
- Для заблокированных пользователей - доступна только запись на консультацию, пока не будет снята блокировка.
- Для посетителей, которым в последний раз оказывалась услуга более года назад - доступно только повторное собеседование. Причем, важно, что отсчет ведется от любого последенго события, связаного с пользователем в таблице servies.
2.1.2
Для некоторых услуг есть отдельные ограничения по минимальному количеству дней, которые должно пройти между получением услуг даного типа, они задаются администартором. Для пользователя выводятся доступные улсуги с учето его истории посещений и данных орграничений. Учитываются только те услуги, на которых он присутсвовал. Если был записан и не пришел - это не учитывается как посещение.
2.1.3
У каждой услуги есть окно бронирования - это максимально удаленное время через которое можно записаться на услуу. Например: если сегодня 01.03, а окно бронирования услуги 14 дней - то максимально я могу записаться на 14.03. Услуги после 14.03 не отображаются на текущий день. 
2.1.4.
Также, есть ограничения по количеству участников услуги. Если суммарное количество участников события превышает максимально воможное для данного события - данное событие не должно выводиться для участника.
2.1.5
Ограничения по количеству участников таймслота: на разные услуги, которые оказываются внутри таймслота могут записываться одни и те же люди и, если суммарное количество уникальных людей, записанных на услуги, которые оказываетюся в рамках данного таймслота - превышает максимально допустимое для данного таймлота, то у постетителя не должны отображаться услуги из данного тайм-слота.

3. Просмотр истории записей и грядущих записей посетителя.
У волонетра должна быть воможность посмотреть историю последних запсией посетителя и его будущие записи, чтобы напоминать о них.

4. Отмена записей посетителей
У волнтера должна быть возможность отменить запись посетителя по его просьбе. Таким образом, человек перестает числиться как записанный на получение услуги.

Основные сценарии использования

1. Запись нового посетителя
Актор: Волнотер
Цель: Записать нового посетителя
Шаги:
1. Выбрать тип записи - новый посетитель
2. Внести имя и фамилию посетителя
3. Выбрать ближайшую доступную дату для единственной доступной услуги - консультации
4. Записать посетителя

2. Запись существующего посетителя
Актор: Волнотер
Цель: Записать существующего посетителя на получение услуги
Шаги:
1. Найти человека по ФИО или id
2. Вбырать услугу из перечня доступных для него 
3. Записать 

3. Запись заблокированного посетителя
Актор: Волнотер
Цель: Записать заблокированного посетителя на получение услуги
Шаги:
1. Найти человека по ФИО или id
2. Увидеть, что человек заблокирован и прочитать комментарий - причину
3. Записать на единственно доступную для него услугу

4. Запись посетителя, который не был больше года
Актор: Волнотер
Цель: Записать существующего посетителя на получение услуги, который не был больше года
Шаги:
1. Найти человека по ФИО или id
2. Увидеть, информационное сообщение о том, что человек не был больше года
3. Записать на единственно доступную для него услугу

  - Поддержка различных браузеров

  - Мгновенное обновление статусов
3. Удобство использования:

- При блокировке участника ему доступны только услуга повторное собеседование

- Если год не получал услуги - снова только повторное собеседование
- Экспорт данных нужен, это удобно
